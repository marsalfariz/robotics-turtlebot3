# line_follower

Line follower robot with a virtual IR (photodiode) sensor array, simulated in **ROS 2 Humble + Gazebo Fortress**.
Final Group Project — the full report is in [`docs/report.md`](docs/report.md) (also exported as `.docx` and `.pdf`).

## Package contents

| Folder / file | Contents |
|---|---|
| `worlds/line_track.sdf` | White floor + black oval line (generated by `scripts/generate_track.py`) |
| `models/line_robot/` | Differential-drive robot 20×12×5 cm + 40×4 px camera used as the IR sensor array |
| `line_follower/ir_sensor_node.py` | Camera image → 5 IR sensor values on `/ir_sensors` (0 = black, 1 = white) |
| `line_follower/line_follower_node.py` | PID controller: `/ir_sensors` → `/cmd_vel` |
| `line_follower/lap_logger_node.py` | CSV log (incl. ground-truth pose) + lap time, written to `~/line_follower_ws/logs/` |
| `config/follower.yaml` | All controller and logger parameters |
| `config/gui_video.config` | Gazebo GUI layout for recording videos (3D view + video recorder) |
| `launch/world.launch.py` | Opens the world only |
| `launch/sim.launch.py` | World + robot + bridge + sensor (+ controller with `follow:=true`) |
| `scripts/run_experiments.py` | Automatic headless experiments → `docs/results.csv` |
| `scripts/make_figures.py` | Report figures → `docs/figures/` |
| `docs/` | Report, results, figures, diagrams (Graphviz sources), simulation video |

## Installation

Ubuntu 22.04, ROS 2 Humble:

```bash
sudo apt install ros-humble-desktop ros-dev-tools ros-humble-ros-gz ros-humble-xacro \
  ros-humble-robot-state-publisher ros-humble-joint-state-publisher python3-matplotlib graphviz
cd ~/line_follower_ws
colcon build --symlink-install
source install/setup.bash
```

## Running

```bash
ros2 launch line_follower sim.launch.py follow:=true                 # robot follows the line
ros2 launch line_follower sim.launch.py                              # robot idle, drive it yourself via /cmd_vel
ros2 launch line_follower sim.launch.py follow:=true headless:=true  # no Gazebo window
ros2 launch line_follower sim.launch.py software_gl:=false          # PC with a real GPU (not a VM)
```

Useful topics: `ros2 topic echo /ir_sensors`, `/line_error`, `/cmd_vel`, `/odom`, `/ground_truth`.

Change parameters in `config/follower.yaml` and launch again (no rebuild needed thanks to `--symlink-install`).

## Experiments and figures

```bash
cd ~/line_follower_ws && source install/setup.bash
python3 src/line_follower/scripts/run_experiments.py --speeds 0.15 0.25 0.35 0.45 --runs 0.45,3.0,0.0  # --runs speed,kp,kd
python3 src/line_follower/scripts/make_figures.py
```

Position-based evaluation (laps, deviation) uses `/ground_truth` from Gazebo, not `/odom`, because wheel odometry
drifts when the wheels slip. The controller itself only uses the IR sensors.

## Notes

- In a VM (VirtualBox/Parallels/VMware) Gazebo often crashes with the virtual GPU; the launch files render on the
  CPU by default (`software_gl:=true`).
- If the Gazebo window is still open after Ctrl+C, run `pkill -f "ign gazebo"` before the next launch — two
  simulations at once interfere with each other.
- The default Ubuntu video player needs `sudo apt install gstreamer1.0-libav` to play the H.264 `.mp4`;
  the `.webm` copy plays without it.
